# C11 threaded pipeline

A compact C11/POSIX threads example with a producer, eight processing stages,
and two consumers.

```text
producer -> stage 1 -> ... -> stage 8 -> consumer 1 / consumer 2
```

## Build and run

```bash
make
./pipeline
```

The `pipeline` executable is generated by the build and intentionally ignored
by Git.

## What it demonstrates

- Mutex-protected bounded queues and condition variables.
- A deliberately slow fourth stage (`nanosleep`) to create queue pressure.
- Non-blocking data delivery with `queue_try_push`: full queues drop data
  instead of blocking their producer.
- Per-channel drop counts printed after every run.
- Per-message monotonic timestamps and end-to-end latency in microseconds.
- Two consumers sharing the final queue.
- Sentinel-based, clean shutdown: stop messages use a reliable blocking path
  so that every stage and consumer exits, even when data messages are dropped.

## Reading the output

Each delivered message includes the consumer that handled it, its transformed
value, and its latency:

```text
consumer 1: message  0: value=36 expected=36 latency=12845 us OK
dropped: channel 1 rejected 8 message(s)
All workers stopped cleanly.
```

The exact consumer assignment, latency, and drop count vary with thread
scheduling. Although removal from the shared queue is FIFO, concurrent
consumers do not guarantee a deterministic visible output order.
